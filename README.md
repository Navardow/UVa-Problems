# Competitive Programming 3

I want to try my hand at solving competitive programming problems. Weirdly, I
find it fun and interesting.

I've taken the initiative to read the book listed above. This repo exists to
hold me publicly accountable, as it would be very embarrassing to have it
public and never make any progress.

I agree that being able to solve problems like those in this book, or
LeetCode-style questions, does not automatically make you a good software
engineer. Many problems are solvable with predetermined techniques and
knowledge of certain data structures and algorithms, and some would even say
you only need to memorize patterns. But knowing the patterns is only the start:
you still have to recognize which one applies, adapt it to the problem, and
prove it is correct and fast enough.

I think of this category of programming as similar to chess. You have
established openings, playstyles, and techniques that help you build a winning
position. Some may even say chess is just pattern recognition, but grandmasters
still have to calculate and plan, and that does not make them any less
impressive. Like competitive programming, chess is very hard to master at a high
level, and learning the patterns is only part of the work.

In any case, if you are truly interested in computers and in making them solve
problems as efficiently as possible, as I am, I think you will find these
problems interesting.
